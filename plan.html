▶ mTLS Connection Lifecycle

The complete flow from JavaScript connect() through TLS handshake with client certificate to encrypted data exchange.

Open Certificate Store & Find Client Cert

Open the requested Windows certificate store and locate the X.509 certificate by subject name or SHA-1 thumbprint. Verify it has an associated private key.

CertOpenStore() CertFindCertificateInStore() CertGetCertificateContextProperty()

Acquire Schannel Credentials

Build a SCHANNEL_CRED structure with the client certificate attached. Protocol versions default to system settings. Acquire an outbound credential handle for the Schannel SSP.

AcquireCredentialsHandle()

TCP Connect

Resolve the target hostname via DNS, then establish a plain TCP socket connection using Winsock.

getaddrinfo() socket() connect()

TLS Handshake Loop

Execute the Schannel handshake loop. Send ClientHello, process ServerHello + server certificate, present client certificate for mutual authentication, establish session keys. Loop on SEC_I_CONTINUE_NEEDED.

InitializeSecurityContext() send() / recv()

Encrypted Data Exchange

Query stream buffer sizes. Encrypt outbound data with header/trailer framing and send. Receive inbound data, decrypt, handle incomplete messages and renegotiation.

QueryContextAttributes(STREAM_SIZES) EncryptMessage() DecryptMessage()

Graceful Shutdown

Send TLS shutdown notification, clean up security context, free credentials, free certificate context, close the TCP socket.

ApplyControlToken(SHUTDOWN) DeleteSecurityContext() FreeCredentialsHandle() closesocket()

async socket.read() → Promise<Buffer | null>

Receive and decrypt data from the TLS connection. Returns a Buffer of decrypted bytes, or null if the connection has been closed by the peer (TLS shutdown or TCP close).

let response = Buffer.alloc(0);
while (true) {
  const chunk = await sock.read();
  if (chunk === null) break;
  response = Buffer.concat([response, chunk]);
}
console.log(response.toString());
async socket.close() → Promise<void>

Perform a graceful TLS shutdown, clean up all native resources (security context, credentials, certificate, socket). Safe to call multiple times — subsequent calls are no-ops.

await sock.close();
example Complete mTLS Request 
const { SchannelSocket, listCertificates } = require('node-schannels');

async function main() {
  // 1. Browse available certificates
  const certs = await listCertificates();
  const mtlsCert = certs.find(c => c.hasPrivateKey && c.subject.includes('MyClient'));
  if (!mtlsCert) throw new Error('Client certificate not found');

  // 2. Connect with mTLS
  const sock = new SchannelSocket();
  const connInfo = await sock.connect({
    host: 'secure-api.example.com',
    port: 8443,
    certThumbprint: mtlsCert.thumbprint,
  });
  console.log(`TLS ${connInfo.protocol} | mTLS: ${connInfo.mutualAuth}`);

  // 3. Send request
  await sock.write(Buffer.from(
    'GET /api/data HTTP/1.1\r\n' +
    'Host: secure-api.example.com\r\n' +
    'Connection: close\r\n\r\n'
  ));

  // 4. Read response
  const chunks = [];
  let chunk;
  while ((chunk = await sock.read()) !== null) {
    chunks.push(chunk);
  }
  console.log(Buffer.concat(chunks).toString());

  // 5. Clean up
  await sock.close();
}

main().catch(console.error);

✓ Design Decisions

Key choices made during planning and the rationale behind each.

Addon Technology
node-addon-api (N-API) over NAN or raw V8. Provides ABI stability across Node.js versions — no recompilation needed when users upgrade Node. Header-only C++ wrapper is ergonomic.
JS API Style
Promise-based, not EventEmitter/streams. Consumer calls read() in a loop, getting back Buffer | null. Simpler mental model, composable with async/await.
Credential Object
SCHANNEL_CRED (not SCH_CREDENTIALS). Broader Windows compatibility (Win 7+). User chose system-default TLS versions, so TLS 1.3–specific SCH_CREDENTIALS isn't required. Can upgrade later.
Async Pattern
Napi::AsyncWorker per operation (connect, read, write, close). Each blocks on a libuv thread and resolves/rejects a promise. Simpler than ThreadSafeFunction since no streaming events needed.
Certificate Store
Any store — user-configurable storeName and storeLocation parameters. Defaults to MY / CurrentUser. Supports LocalMachine for service accounts.
Cert Lookup
Subject name + SHA-1 thumbprint + enumeration. Subject uses substring match (CERT_FIND_SUBJECT_STR). Thumbprint uses exact hash match (CERT_FIND_SHA1_HASH). listCertificates() lets users browse before connecting.
TLS Versions
System default — set grbitEnabledProtocols = 0 in SCHANNEL_CRED. Lets the OS manage which protocols are enabled via Group Policy / registry. No hardcoded protocol versions.
Error Handling
Reject with descriptive errors — use FormatMessage for Win32 errors and map SSPI status codes to readable strings. Include the hex error code in the message (e.g., "TLS handshake failed: SEC_E_CERT_UNKNOWN (0x80090327)").

⚠ Gotchas & Pitfalls

Known sharp edges in the Schannel API that the implementation must handle carefully.

SEC_E_INCOMPLETE_MESSAGE

Both handshake and decrypt can return this. It means the TCP recv didn't receive a complete TLS record. Must accumulate data in a buffer and retry the operation with the combined data. Never discard partial data.

SECBUFFER_EXTRA

After DecryptMessage or InitializeSecurityContext, the EXTRA buffer may contain unconsumed bytes belonging to the next TLS record. Must carry them forward to the next recv cycle or they're lost.

Private Key Required

A certificate without an associated private key cannot be used for mTLS — Schannel will silently fail to present it. Always verify CERT_KEY_PROV_INFO_PROP_ID on the cert context before using it.

Thread Safety

InitializeSecurityContext is NOT thread-safe on the same context handle. Since we use AsyncWorkers on libuv's thread pool, we must ensure only one operation runs at a time per socket. Serialize operations via the JS promise chain.

Session Caching

Schannel automatically caches TLS sessions (10h default). Same process + same target name + same credential = session resume. This is usually good, but can mask cert issues during testing.

SEC_I_RENEGOTIATE

DecryptMessage can return this during data exchange, meaning the server wants to renegotiate. Must re-enter the InitializeSecurityContext handshake loop before continuing to read data.

Buffer Sizing

Always query SECPKG_ATTR_STREAM_SIZES after handshake. The header, trailer, and max message sizes vary by negotiated cipher suite. Never hardcode buffer sizes.

2 MB Item Limit (if storing in Cosmos DB)

If certificate metadata or TLS session state is persisted to Azure Cosmos DB, keep items under 2 MB. Certificate blobs can be large — store references, not raw certs.
